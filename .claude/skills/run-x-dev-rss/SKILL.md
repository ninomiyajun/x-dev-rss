# x-dev-rss の起動・確認・停止

パスはすべてリポジトリの根からの相対である。

## 前提

- Node.js の 26 系以上（`package.json` の `engines` が `>=26`）と npm を使う。TypeScript は Node.js が型を除いて直接実行するので、
  ビルドしない。
- 依存は `npm ci` で入れる。
- 待ち受けの先は無い。サーバーではなく、1 回動いて終わるコマンドなので、ホストとポートを選ばない。
- 秘匿値は `~/.config/x-dev-rss/secrets.env`（`X_USERNAME`・`X_AUTH_TOKEN`・`X_CT0`・`SLACK_WEBHOOK_URL`）からアプリが読む。
  エージェントはこのファイルを読まず、値を表示しない。ファイルの権限は 600 にする（所有者以外にも読める権限だと、アプリが止まる）。
- 環境変数 `NODE_DEBUG` を付けて起動しない（送り先が出力に出るおそれがあるので、アプリが止まる）。
- 対象のアカウントは `config/accounts.json`（既定は @AnthropicAI だけ）。

## 起動のコマンド

- `node src/index.ts [--config <パス>] [--state-dir <パス>] [--secrets <パス>] [--dry-run]`（`npm run start` も同じ）。
  すぐ終わるので、前面で実行する。
  - `--state-dir`: 通知済みの記録とロックの置き場。既定は `$XDG_STATE_HOME/x-dev-rss`（無いか、絶対パスでなければ `~/.local/state/x-dev-rss`）。
  - `--secrets`: 秘匿値のファイル。既定は `~/.config/x-dev-rss/secrets.env`。
  - `--config`: 対象のアカウントの設定。既定は `config/accounts.json`。
  - `--dry-run`: X から取得するだけで、Slack へ投稿せず、記録も読み書きしない（試し取得）。
- 引数なしの実行は、本物の X から取得し、本物の Slack のチャンネルへ投稿し、所有者の本物の記録を書き換える。確かめのために
  動かすときは、必ず `--state-dir` に一時ディレクトリ（`mktemp -d /tmp/x-dev-rss.XXXX` で作ったもの）を渡す。

## 起動の完了の確かめ方

- 通常の実行: 終了コードと最後の行で確かめる。成功すると「通知した件数: <数>」の行が出て、終了コード 0 で終わる。
  取得や投稿の失敗、設定や記録が読めないときは、その旨の行が出て、終了コード 1 になる。ほかの実行が動いているときは、
  その旨の 1 行で終了コード 0。秘匿値が足りないときは、足りない変数の名前の 1 行で終了コード 1。知らない引数は終了コード 2。
- 試し取得（`--dry-run`）: 取得した各ポストの ID・日本時間の日時・種類・固定表示・順位の行と、取得の止まり方の行、
  X への要求の回数の行が出て、終了コード 0 で終わる。Slack へは何も投稿されず、`--state-dir` にはロックしか作られない
  （終わると消える）。

## 止め方と止まったことの確かめ方

1 回動いて自分で終わるので、止める操作は要らない。止まったことは、起動したコマンドが終了コードを返して戻ったことで確かめる。
`--state-dir` に run.lock が残っていないことも確かめる（残っていても、持ち主のプロセスが終わっていれば次の実行が取り除く）。

## 確認用のデータで起動する方法

- X と Slack へ通信せずに決まったデータで動かす方法は、自動の試験（`npm run test`）である。実行の流れの試験
  （`src/app/run.test.ts`）が、取得と投稿の口を偽物に差し替えて、仕様の各場面を動かす。
- 本物の X から取得するが Slack へ投稿しない確かめは、`node src/index.ts --dry-run --state-dir <一時ディレクトリ>` で行う。
- 終わった後の一時ディレクトリは消す。
