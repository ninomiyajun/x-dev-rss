# 0002 層を 4 つに分け、依存の向きを lint で守らせる

## 背景

最初の機能（X の取得と Slack への投稿）では、仕様の 23 の受け入れ基準を、本物の X と Slack を使わずに試験で確かめる必要が
あった。そのためには、取得と投稿と時刻と待ちを差し替える口が要る。また、取得用の X のアカウントが凍結されたときは、無料で
使える別の取得のサービスへの切り替えを所有者に提案することになっており、取得の手段を替えやすい形にしておきたい。

## 判断

入口（`src/index.ts`）・実行の流れ（`src/app/`）・判定と文面（`src/domain/`）・外との接続（`src/adapters/`）の 4 つに分ける。

- 実行の流れは、判定と文面だけを使い、node の組み込みも使わない。外とのやりとり・待ち・時刻は、口の型（`src/app/ports.ts`）を通す。
- 外との接続が読んでよい app のファイルは `src/app/ports.ts` だけとする。
- 取得のライブラリを読み込んでよいのは `src/adapters/x-scraper.ts` だけとする。
- この決まりを `eslint.config.js` の `no-restricted-imports` で守らせる。

## 検討した代わりの案

- 入口の 1 ファイルに全部を書く案: 試験で差し替える口が作れず、取得のライブラリの型が全体へ広がるので採らない。
- 判定と文面を実行の流れに混ぜる 3 つの層の案: 選び方と文面の試験に口の偽物が要るようになり、得が無いので採らない。
- 口の型を `src/domain/` に置く案: 外との接続が app を一切読まずに済むが、秘匿値の束・ロック・待ち・時刻のような実行の流れの
  都合の型が判定と文面に入り、入出力を持たないという責務の線が崩れるので採らない。

## 結果

取得の手段を替えるときに直すのは、`src/adapters/x-scraper.ts` と入口の組み立てだけになる。逆向きの読み込みは lint が失敗にする。
外との接続から `src/app/ports.ts` への読み込みが 1 本残る（型だけの読み込み）。
