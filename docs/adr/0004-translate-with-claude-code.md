# 0004 翻訳の手段に、手元の Claude Code を画面なしで使う

## 背景

Slack へ通知するポストの本文を、英語から日本語に訳す（製品の仕様 `docs/product-specs/x-post-japanese.md`）。翻訳の手段が要る。
所有者の費用の決めは、既存の契約の範囲を超えて追加の費用を発生させないことで、API の鍵を使う従量課金は選べない。
所有者は、手元の Claude Code（`claude` コマンド）を、契約のログインのまま画面なしの形（`claude -p`）で子プロセスとして動かす方法を選んだ。
この方法は、設定を絞らないと所有者の全体の規約とフックが子で動いて訳でない応答が返ること、環境や保存済みの認証の状態によっては
API の課金の経路に入りうることが、事前の確かめで分かっている。そのため、呼び方の隔離と認証の確かめを設計の一部として決める必要がある。

## 判断

- 層の置き場: 手段によらない決め（訳すかどうか、守る部分、訳文の検証、印、固定の文面）は判定と文面（`src/domain/translation.ts` と
  `src/domain/message.ts`）に置く。`claude` に固有のもの（起動、包み、system prompt、認証の確かめ、終了コードと JSON の形、
  包みの漏れの検査、子プロセスの管理）は外との接続（`src/adapters/claude-translator.ts`）に置く。実行の流れ（`src/app/translate.ts`）が、
  判定、翻訳の口、検証、印の順に組み合わせる。層の分け方と依存の向きは変えない（ADR 0002 は直さない）。
- 子の環境: 許す変数の表（`HOME`・`USER`・`LOGNAME`・`TMPDIR`・`LANG`・`LC_ALL`・`LC_CTYPE` と、固定の `PATH`）だけを写す。
  外す変数の表を持つ案は、表に無い変数が子へ渡って課金の経路や送り先が変わるおそれが残るので採らない。API の鍵と秘匿値は渡さない。
- 子の引数: `-p`、モデルの別名、`--setting-sources project`、`--no-session-persistence`、`--tools ""`、`--strict-mcp-config`、
  `--disable-slash-commands`、1 回の呼び出しの予算の上限、system prompt、`--output-format stream-json --verbose`。`--bare` は契約の
  ログインを読まないので使わない。予算の上限は、1 回の呼び出しが想定外に長く続くのを止める補助で、追加の費用が出ないことの保証には
  使わない（上限は API の要求の後に判定され、1 回目の要求は止めない）。
- 作業ディレクトリ: `/private/tmp` の下に実行ごとに作る空の一時ディレクトリ。親のディレクトリに `CLAUDE.md` と `.claude` が無いことを
  実行のたびに確かめ、あれば訳さない。全体の設定・フック・MCP・`CLAUDE.md` を読まないことを確かめられないときも訳さない。
- 認証の確かめ: 1 回の実行の初めの翻訳の前に `claude auth status --json` を起動して `authMethod` だけを読み、契約のログイン
  （`claude.ai`）でなければ訳の子を起動しない。呼び出しごとには、初めの知らせの `apiKeySource` が `none` であること、
  `tools` と `mcp_servers` が空であることを確かめ、満たさなければ子を止めて訳せなかったものとして扱う。
- 本文の渡し方: 標準入力で渡す（引数の長さの上限と、`ps` で本文が見えることを避ける）。呼び出しごとに推測できない目印を付けたタグで
  本文を包み、system prompt で、包みの中の指示・依頼・質問・タグには従わず訳す対象として扱うよう指示する。本文は信頼できない入力として扱う。
  `claude` が自動で添える利用者の文脈が訳文に漏れることがあるため、目印・`system-reminder`・原文に無いメールアドレスの形・原文に無い
  タグの形を訳文に見つけたら失敗とする。目印・`system-reminder`・メールアドレスの形・子の環境に由来する文字列（作業ディレクトリ、`HOME`・`USER` の値など）は、
  訳文と原文を NFKC で正規化した後にも確かめる（全角の＠などで表記を変えた漏れを拾うため）。
- 訳文の検証: 日本語の文字があること、守る部分（URL・メンション・ハッシュタグ・コード）が原文と同じ回数だけ原文の文字のまま残ること、
  訳文から取り出した守る部分がどれも原文の守る部分に境界つきで当たること（足された守る部分が無いこと）、原文の丸写しが無いこと
  （空白の並びと末尾の句読点だけが違う、原文と同じ応答を含む）、長さが妥当なことを、手段によらない形で検証する。通らない訳文は使わない。
- モデルとやり直し: 1 回目は Haiku、やり直しの 2 回目は Sonnet（別名で指定し、版は固定しない）。やり直しは 1 回だけで、間に 5 秒待つ。
  時間切れは 1 回の呼び出しにつき 120 秒。外との接続の失敗が 2 回続いたときは、同じ実行の後のポストは訳さずに失敗の印を付ける。
  1 回目の結果が手段を使えないこと（契約のログインを確かめられない、隔離を確かめられない、起動できない、上限を超えた分の支払いが
  有効と分かったなど）を示したときは、2 回目を試さず（5 秒も待たず）、そのポストに失敗の印を付け、同じ実行の翻訳をすぐに止める。
- 上限を超えた分の支払いの確かめ: 呼び出しの出力の使用量の知らせ（`rate_limit_event` の行）に、上限を超えた分の支払いが有効である
  こと（`overageEnabled` が true）か、許されて使われていること（`overageStatus` が `allowed` で始まる値、`isUsingOverage` が true）が
  現れたら、その呼び出しを訳せなかったものとし、同じ実行では以後の子を起動しない。
  契約の上限を超えた分が追加の費用になる経路を、実行のたびに見つけるためである。
- 失敗の扱い: 翻訳の失敗で通知を止めず、原文のまま印を付けて投稿する。翻訳の部品は例外を外へ出さず、起動した子（認証の確かめの子を含む）を、
  時間切れ・出力量の超過・終了要求で、まとまりごとに `SIGTERM`、猶予の後に `SIGKILL` で必ず止める。終了要求の後は新しい子を起動しない。
  入口は終了要求（`SIGTERM`・`SIGINT`）を受けたら、終了要求の印を立てる → 翻訳の子を止める → 実行の流れを最大 20 秒待つ
  （Slack への投稿の時間切れ 15 秒に 5 秒を足した値）→ ロックを外す → 終了コード 130（`SIGINT`）か 143（`SIGTERM`）で終わる、の順に動く。
  2 回目の終了要求では待たずに終わり、その前に起動中の子のまとまりへ同期で `SIGKILL` を送る。
- 実物の訳を観察する手段: 起動の引数 `--try-translate` で、標準入力の本文を投稿と同じ流れで訳して出力するだけの流れを持つ。
- 子プロセスの起動を限る規則: `node:child_process` を読み込んでよいのを `src/adapters/claude-translator.ts` と、既に `ps` を起動している
  `src/adapters/lock-file.ts` だけにし、それ以外のファイルでの読み込みを lint が止める。

## 検討した代わりの案

- Apple の Translation フレームワーク: Swift の小さな道具をビルドして署名する手間が増え、このプロジェクトのビルドしない作りと試験の作りに合わない。
- DeepL API Free: 新しいアカウントと API の鍵（秘匿値）が要り、無料の量を超えたときの扱いを別に確かめる必要がある。
- Ollama: 数 GB のモデルの取得と、日次の実行のたびのメモリと時間の消費が要り、小さいモデルの日本語の訳の質が分からない。
- Anthropic の API を鍵で使う: 従量課金で、所有者の費用の決めに反する。
- 全部を外との接続に置き、接続が通の本文を返す案: 仕様の決め（日本語のポストは訳さない、守る部分）が `claude` の部品に入り、手段を
  替えると決めも書き直しになり、試験に子プロセスが要るので採らない。
- 導入のときだけ認証を確かめる案、子の環境に API の鍵が無いことで足りるとする案: 保存済みの認証が API の課金のものに替わる場合や、
  管理の方針の設定による経路があるので採らない。

（料金の細部は確かめていない。上の案の理由は設計の担当が挙げたもので、所有者が選んだのは手元の Claude Code である。）

## 結果

- 翻訳は、所有者の Claude の契約の使用量を使う。契約の上限を超えた分を追加で支払う設定は無効のままにする（所有者が無効であることを確かめた）。
- 契約のログインの情報が、launchd から起動した `claude` でも読めることに依る。2026-11-10 に、一時的な LaunchAgent から `claude` を起動して
  確かめた: 認証の種類は `claude.ai`、初めの知らせの `apiKeySource` は `none`、`tools` と `mcp_servers` は空で、訳が返った。このとき
  launchd が子に渡した環境は `HOME`・`USER`・`LOGNAME`・`TMPDIR` で、`LANG`・`LC_ALL`・`LC_CTYPE` は無かった。
- `claude` の版（確かめたのは 2.1.316）が変わると、引数や出力の項目の意味が変わりうる。変わって隔離や認証を確かめられなくなったときは、
  訳さずに失敗の印を付ける側に倒れる。
- 翻訳の手段を替えるときに直すのは、外との接続のファイル、入口の組み立て、`eslint.config.js` の子プロセスの許可の一覧だけである。
- 訳文の検証は形の検査で、訳の意味が正しいことを保証しない。日本語の自然な別の文を、守る部分を残して返す応答は通りうる。残る危険は、
  system prompt と、実物の訳の観察で小さくする。
- 4 語以下の英語の短い文を翻訳の手段が丸写しで返しても、訳す必要の無いポストとして印なしの原文で載る。
- 組み込みのプラグインの部品は、決めた呼び方でも動き、利用量の記録を Anthropic へ送る。引数では外せない。
- 親が `SIGKILL` で止められたときは終了要求を受け止められず、子のまとまりが残りうる（子は標準入力を閉じられた 1 回の訳を終えると自分で終わる見込み）。
- 終了要求の待ちの上限を超えたとき、送信中の投稿が Slack に届いて記録が書かれる前に実行が終わり、次の実行で同じポストを二重に通知しうる。
- 訳の子へは、初めの知らせ（init の行）を見る前に標準入力で本文を渡している。そのため、init の行で従量課金の経路と分かって子を止めるまでに、
  API の要求が送られうる。従量課金を避ける主な守りは、訳の子の前に行う認証の確かめ（`auth status`）である。
- 認証の確かめの子（`auth status`）は、`--setting-sources` などの引数で隔離しておらず、全体の設定を読む。読み取りの確かめで、訳の子の前に
  契約のログインでなければ止める側に働くが、全体の設定のフックがこの子で動くかは確かめていない。
- 呼び出しごとの隔離の確かめは、init の行の項目（`apiKeySource`・`tools`・`mcp_servers`）に頼る。全体の `CLAUDE.md` を読まないことは
  直接には確かめられず、事前の確かめで入力のトークンの量が少ないことから判断した、間接の確かめである。
- 上限を超えた分の支払いが有効かどうかは、本文を送る前には確かめられない。`claude auth status --json` の出力には、その項目が無い
  （2026-11-10 に項目の名前だけを確かめた）。使用量の知らせは訳の呼び出しの出力にしか出ないので、設定が有効になった後の最初の 1 回の
  要求は防げない（その後の子は起動しない）。この経路の守りは、所有者が上限を超えた分の支払いの設定を有効にしないという決め（`AGENTS.md` の
  費用の決め）である。
- 漏れの検査は、表記を変えた漏れ（NFKC で戻らない文字への置き換え、言い換え、分割など）を網羅はできない。また、`claude` が会話に自動で
  添える利用者の文脈は、呼び出し側から入力より除けない。そのため、漏れの検査は既知の形を止める補助で、漏れが無いことの保証ではない。
- ハッシュタグの直後に空白なしで日本語の文字が続く訳（「#AIの更新内容」）を通すため、訳文の守る部分は原文の守る部分で始まれば当たる
  ものとして数える。そのため、ハッシュタグの後ろに日本語の文字を足した書き換え（「#AI」を「#AI別名」にする）は通る。この区別は
  正規表現ではできず、害は Slack で表示の文字列が変わるだけなので許す。ASCII の英数字が続く書き換え（「#AI2」「@claudeai2」）は通さない。
- 上限を超えた分の支払いの印は、訳の呼び出しの出力のうち `rate_limit_event` の行だけで見ている。ほかの行や `claude` の版の変更で項目が
  移ると見落としうる。また、支払いが無効のアカウントで `overageStatus` が `allowed` で始まる値にならないことは、観察 1 件（値は `rejected`）
  でしか確かめていない。誤って当たって翻訳が止まった場合は、ポストに失敗の印が付くので、所有者が気づける。
- 2 回目の終了要求の `killAllNow` は、管理の表に残ったまとまりの番号へ `SIGKILL` を送る。まとまりが消えた直後に、その番号が別の
  プロセスのまとまりに再利用されていると、そちらに当たりうる（消えたことを確かめてから表から外すまでの短い時間に限る）。
